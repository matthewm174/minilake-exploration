Runtime topology — processes, ports and state on disk

Two long-running services (minilake on :8000, Postgres on :5439) plus a short-lived pipeline process. lake.py reaches minilake over REST for catalog work, but reads and writes data files directly — exactly like a Spark job that registers tables in Unity Catalog and writes to S3 itself.

Start order

.\start-minilake.ps1 (leave open) → start Postgres → python pipeline\lake.py all. lake.py exits with a clear message if either service is unreachable.

Persistence caveat

Stop minilake with Ctrl+C. After a crash the registry may be stale; lake.py setup re-registers every folder under s3/ that has a _delta_log. Data is never lost — it lives in the Delta files.

Overrides

MINILAKE_HOST, MINILAKE_DATA_DIR, LAKE_S3_ROOT, REDSHIFT_DSN, REDSHIFT_PASSWORD (default localdev, local-only).
