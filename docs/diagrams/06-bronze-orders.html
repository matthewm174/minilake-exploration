-- Raw order events (JSON lines, nested items kept as-is), duplicates and1
-- bad records included.
SELECT
    order_id, customer_id, order_ts, status, channel,
    items,                                                    2
    '${LANDING_URI}/orders/' || parse_filename(filename)
        AS _source_file,                                    3
    now() AS _ingested_at                                    4
FROM read_json(
    '${LANDING}/orders/*.jsonl',                            5
    format = 'newline_delimited',
    filename = true,                                         3
    columns = {                                               6

        order_ts: 'VARCHAR',    status: 'VARCHAR',
        channel:  'VARCHAR',
        items: 'STRUCT(sku VARCHAR, qty VARCHAR, unit_price VARCHAR)[]'
    }
)

What each marker does

  • 1First comment line → the UC table comment (_comment()).
  • 2Nested items array kept intact; exploding it is silver's job.
  • 3filename = true exposes the file path; it is rewritten to its s3:// form as _source_file. Silver uses it as the "newest delivery wins" tie-breaker.
  • 4_ingested_at records when this bronze build ran.
  • 5_render() swaps ${LANDING} for the local landing folder and ${LANDING_URI} for s3://acme-landing/raw. The glob picks up every landed day.
  • 6An explicit all-VARCHAR schema: no type inference, so a bad value can never fail ingestion. Typing happens in silver.
